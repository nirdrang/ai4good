## Type facts that closed the unverified SDK points

Line numbers are `node_modules/ai/dist/index.d.ts` unless named otherwise.

1. **Transport options and `prepareSendMessagesRequest`.** `DefaultChatTransport` is at 5841–5842 and takes `HttpChatTransportInitOptions` at 5780–5826: `api`, `credentials`, `headers`, `body`, `fetch`, `prepareSendMessagesRequest`, `prepareReconnectToStreamRequest`. `headers` is `Resolvable<Record<string, string> | Headers>` (5795), so an async function is legal. `PrepareSendMessagesRequest` is at 5737–5758. It receives `messages`, `api`, `headers`, `trigger`, `messageId`, and must return `{ body: object; headers?: …; api?: … }`. Returning `body` replaces the default `{ id, messages, trigger, messageId }` (gotcha 5). The page returns `{ body: { organizationId, projectId, message } }` and does not return `headers`, so the auth headers stay.

2. **`Accept` and extra request headers.** The types do not mention `Accept`. `HttpChatTransport.sendMessages` (source `node_modules/ai/src/ui/http-chat-transport.ts` 193–202) sets only `Content-Type: application/json` plus the resolved headers. The SDK does not set `Accept: text/event-stream`. The page sets it in `headers`. No other custom header is added. `Content-Type: application/json` is CORS-safelisted. `Accept` is CORS-safelisted. `authorization` and `apikey` are on the function allow list (explanation section 2).

3. **Stream parts on `UIMessage.parts`.** `UIMessage` is at 1845–1868. `parts` is `UIMessagePart[]` (1870). Text is `TextUIPart` `{ type: 'text'; text: string; state?: 'streaming' \| 'done' }` at 1874–1888. Custom data is `DataUIPart` at 2011–2017: `{ type: \`data-${NAME}\`; id?: string; data: DATA_TYPES[NAME] }`. A `data-turn` wire part lands as `part.type === 'data-turn'` with `part.data` equal to the JSON 200 body of explanation section 5 (`ok`, `turn`, `reply`, `elicitation`, `allowance`). `allowanceFromMessages` reads `part.data.allowance`.

4. **`stop()`, status after abort, partial text.** `ChatStatus` is `'submitted' \| 'streaming' \| 'ready' \| 'error'` at 5554. `stop` is at 5711–5713: “Abort the current request immediately, keep the generated tokens if any.” `useChat` returns `stop` via the Pick at `@ai-sdk/react/dist/index.d.ts` 114. On abort the implementation sets `status` to `'ready'`, not `'error'` (`node_modules/ai/src/ui/chat.ts` 825–841). The page watches `streaming|submitted → ready` after a Stop press and then reloads `discovery-conversation`.

5. **Non-2xx body to `onError`.** `ChatOnErrorCallback` is `(error: Error) => void` at 5564. `ChatInit.onError` is at 5606. The transport already throws the response text: `createUIApiCallError` sets `message: responseBody || fallbackMessage` (`node_modules/ai/src/ui/create-ui-api-call-error.ts` 12–21), used from `http-chat-transport.ts` 204–209. **No fetch wrapper.** The page runs `refusalFromResponseText(error.message)`.

6. **Submit name.** `sendMessage` at 5675–5690. `UseChatHelpers` picks `sendMessage` (`@ai-sdk/react/dist/index.d.ts` 114). There is no `append` / `handleSubmit` on `useChat`. The composer calls `sendMessage({ text })`.

7. **Typed `UIMessage` generic for `data-turn`.** `UIMessage<METADATA, DATA_PARTS, TOOLS>` at 1845. Default `DATA_PARTS` is `UIDataTypes` = `Record<string, unknown>` at 1823, so `data-turn` is already a legal `data-${string}` part and `part.data` is visible without a custom generic. A generic of `{ turn: { allowance: Allowance; … } }` would type `part.data`; the page does not need it because `allowanceFromMessages` narrows at runtime.

8. **`reconnectToStream`.** Declared on `HttpChatTransport` at 5837. `useChat` has `resume?: boolean` (`@ai-sdk/react/dist/index.d.ts` 128–131). The implementation default is `resume = false` (`node_modules/@ai-sdk/react/src/use-chat.ts` 75). The page does not pass `resume` and does not call `resumeStream`. Discovery has no reconnect route.

9. **`react-refresh/only-export-components` on `export const Route`.** Not a `.d.ts` fact. `eslint.config.js` line 35 allows constant exports. CI does not run eslint. Typecheck does not warn.

## Deviations

1. **No fetch wrapper.** The brief allowed this when the transport already throws the response text. It does. See type fact 5.
2. **`ai` 7.0.102 and `@ai-sdk/react` 4.0.105**, not 7.0.105 / 4.0.108. `bun add` resolved these. `react-markdown` matched 10.1.0.
3. **`at:selftest` exit 1** is pre-existing on this worktree. This unit did not touch the skill files. The brief forbids edits under `supabase/` and `tests/`.
4. **This commit mixes Lovable territory (`src/`) with Claude territory (`.claude/`, `loop/`).** The unit brief named every file. CI’s ownership guard will fail a single pull request that contains both. The lead must split, or the founder must allow the mix.
5. **`allowanceFromMessages` reads `part.data.allowance`**, not `part.data` itself. The wire `data-turn` payload is the JSON 200 body (explanation section 6). The return type is `Allowance`. A raw `part.data` would not be an `Allowance`.
6. **Prepare-script diagnostics go to stderr; the JSON object is the only `console.log`.** So a driver can parse stdout.
