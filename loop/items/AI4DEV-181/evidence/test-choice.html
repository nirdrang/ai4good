How should the tests prove the real backend works?

One decision for the Discovery wiring item. Three pictures, then the choice.

1. Today: the tests run on a fake backend with a script

Test clicks "Send"→Screen→Fake backend
(fixed script)→Always the same reply:
"38 of your 45 volunteers"

The test checks the exact words. This works, because the script never changes.

2. The problem: the real backend has a real AI

Test clicks "Send"→Screen→Real backend→Real AI (Haiku)→Different words
every time
The test checks…On the real backend
Exact reply wordsFails: the AI words it differently each time
"38 of your 45 volunteers" from the uploaded fileFails: the test file is only a few letters, not a real spreadsheet
Fuel balance "$1.60"Fails: fuel does not exist in the real backend yet
Answer saved, brief updated, 1 credit used, file read, Finish recordedCan pass: these do not depend on the AI's words

3. The three choices

A. Two levels of checking (recommended)

Fake backend→checks exact words
Real backend + real AI→checks that things work:
saved, brief changed, 1 credit, file read, Finish

Fuel steps run only on the fake backend until the fuel feature exists. No new test machinery.

B. A scripted fake AI behind the real backend

Real backend→Fake AI that always gives the scripted words

The tests stay word-for-word the same. But the project rule says the test harness gets no new machinery, so this needs your exception. Fuel steps still cannot pass.

C. Looser checks everywhere

Both backends→check only "a reply arrived", "some facts found"

Simple, but the fake-backend tests also become weaker.
