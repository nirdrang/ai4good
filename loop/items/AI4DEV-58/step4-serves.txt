WHY EACH LINE IS THE EVIDENCE IT CLAIMS TO BE
---------------------------------------------
1. The preflight is answered 204 with EXACTLY the four allowed headers and two methods that
   `CORS_HEADERS` in supabase/functions/_shared/edge.ts spells. A container that merely listens
   would not produce that header set, so this says our module loaded, not that a port is open.

2. The unauthenticated POST is refused 401 with our own sentence. That refusal comes from
   `resolveCaller` - the function this item widened to carry `githubHandle`, and the one that now
   imports `./github.ts`. A module whose new import failed to resolve inside the Deno edge runtime
   would 500 or fail to boot; a 401 carrying our text means the changed module is the one running.

3. `create-organization` still serves. It shares the widened `Caller` type and reads only
   `caller.id`, so this is the check that widening the type broke nothing beside it.

4. `/auth/v1/settings` reports github: true, alongside the google: true the predecessor item
   established. This is the whole of what the `[auth.external.github]` block can prove: the
   configuration is WELL-FORMED and the stack started with it. It is NOT a claim that any GitHub
   handshake works.

5. No GitHub OAuth client id is set in the environment. This is the EXPECTED case and blocks
   nothing - creating the OAuth app is a founder-manual step, exactly as it was for Google. It is
   recorded because step 6(f2) is conditional on it, and because a stack reporting github: true with
   no real credential must never be reported as more than well-formedness.
