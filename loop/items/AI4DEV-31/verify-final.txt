WHAT THIS ITEM CLOSES ON — the claim, stated once, in the words every comment now uses
--------------------------------------------------------------------------------------

  CLOSED   A suite can no longer NAME the seam types. Every route the old API invited is shut:
           no shape arguments on `bindSuite` / `atTest` / `defineEvidenceCapture`, no
           shape-parameterized type exported for a body to annotate with, no `EvidenceCapture`
           constructor to reach, no exported function declaration to merge a fresh overload onto,
           and no interface on the seam path to merge a member into. The requirement literal ties
           the map key, the module the types are read from and the module the loader imports to one
           self-declared value, checked at compile time and again at run time — and that run-time
           check now has both of its failing paths under test.

  OPEN     A deliberate structural reconstruction of the widened type out of the derived ones, plus
           the pre-existing escapes: `any`, `as`, `@ts-ignore`, `@ts-nocheck`, mutating an adapter
           after it is built, and pointing `AT_REPO_ROOT` at another tree. No type can reject the
           reconstruction; rejecting it needs a source-inspection pass, filed as its own item.

The threat model is a suite DRIFTING from its harness with nobody able to notice — an honest
mistake that type-checks green. That is closed. An author who sits down to defeat the type system
is not, and this item no longer says otherwise anywhere.
