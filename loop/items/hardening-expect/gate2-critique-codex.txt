1. Suite/import failures can be hidden by expected reds.

SEVERITY: blocker [FALSE-GREEN-CLASS]

`VitestJson` keeps only assertion results and test totals ([runner.ts:780](/C:/Users/nirdr/Downloads/ai4good-expect/tests/at/harness/runner.ts:780)); suite-level metadata is discarded ([runner.ts:1154](/C:/Users/nirdr/Downloads/ai4good-expect/tests/at/harness/runner.ts:1154)). An extra test file that throws during import can leave all expected assertion counts unchanged while Vitest reports a failed suite. With declared reds, `success === false` and the nonzero process exit are treated as expected, so `--expect` can return 0.

Minimal fix: preserve and reject unaccounted suite-level error/status fields from the JSON report, allowing only failures attributable to declared red assertions.

2. A `__proto__` red declaration bypasses malformed-manifest validation.

SEVERITY: blocker [FALSE-GREEN-CLASS]

`red` is populated into a normal `{}` ([expected.ts:148](/C:/Users/nirdr/Downloads/ai4good-expect/tests/at/harness/expected.ts:148), [expected.ts:150](/C:/Users/nirdr/Downloads/ai4good-expect/tests/at/harness/expected.ts:150)). JSON containing `"red": {"__proto__": {...}}` invokes the prototype setter, so the key disappears from `Object.keys`; the AT-id validation and bijection check then ignore it ([expected.ts:153](/C:/Users/nirdr/Downloads/ai4good-expect/tests/at/harness/expected.ts:153)). A malformed declaration can therefore pass with an otherwise all-green suite.

Minimal fix: use `Object.create(null)` for declaration maps or define keys with `Object.defineProperty` before validating them.

3. Exact text does not prove a genuine `AtPending` or `CapabilityPending`.

SEVERITY: blocker [FALSE-GREEN-CLASS]

Minimal fix: carry a structured error kind/provenance field through the report and match that, rather than relying on the error’s printable name and message.
