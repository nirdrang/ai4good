================================================================================
PROBE 2 — the JS runtime. Does trim() strip U+FEFF?
================================================================================

Command, verbatim:

  PS> bun -e "console.log(JSON.stringify({ trimmedIsEmpty: '\uFEFF'.trim() === '', codePoint: '\uFEFF'.codePointAt(0), trimmedLength: '\uFEFF'.trim().length, runtime: 'bun ' + Bun.version }))"

The character is written as the JavaScript escape \uFEFF rather than as the raw character. Windows
PowerShell does not expand \u in a double-quoted string, so bun received the escape and JavaScript
resolved it. The reported codePoint 65279 is 0xFEFF, which proves the string under test is the one
the ruling names.

Output, verbatim:

  {"trimmedIsEmpty":true,"codePoint":65279,"trimmedLength":0,"runtime":"bun 1.3.14"}

Reading: TRUE. A U+FEFF-only string trims to the empty string in the suite's runtime, and the
trimmed length is 0. So validateCompleteSignup's presence-and-blank checks refuse a FEFF-only
signer field: the value trims to the empty string and the check names its field.

================================================================================
WHAT THE TWO READINGS TOGETHER MEAN
================================================================================

The two blank floors disagree, and they disagree in the safe direction for every caller that goes
through the edge function. Through the deployed path a FEFF-only value never reaches the database:
the validation layer trims it to empty and refuses the completion. The only writer that can persist
a FEFF-only signer field is a caller holding the service key that calls public.complete_signup
directly and bypasses the edge function — the same trusted-key caller, and the same boundary, that
terra finding 1 describes.

Per the ruling this is an accepted residual, stated rather than moved. Chasing the ECMAScript
whitespace set through PostgreSQL character classes would reproduce, character by character, the
two-source drift hazard that finding 1 rejects.
