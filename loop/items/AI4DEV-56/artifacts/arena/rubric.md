# Arena rubric: one design for the admin-operations subtree

The artifact each runner produces: a design package per the architect rationale template (usage first, then types, signatures, module map, migration sketch with `not implemented` bodies, and prose rationale), covering all six units of `loop/items/AI4DEV-56/brief.md`. The picker grades on these criteria, 0 to 3 each.

1. **One boundary, mechanically enforced.** Every write route registers through ONE mandatory lifecycle-gate boundary, and a conformance check in the loop tier (so it runs in CI) fails a fourth write route added without registering. The check reads the tree, not a list somebody remembers. The operator path and the service-role RPC path are named and either covered or explicitly out with a reason.
2. **History preserved, attribution intact.** Contact transfer moves the seat to the new account and deactivates the old one without rewriting `acknowledgments`, `org_memberships` history, `projects` or `volunteer_profiles` attribution. The design says row by row what changes and what does not, and it is one transaction.
3. **Append-only in the schema, not in prose.** The audit table cannot be updated or deleted by any client role or by the service role, stated as grants, policies and triggers the static scan and the live catalog check can pin. Role changes and contact transfer both write it from the same path.
4. **Every id has a body and an honest tier shape.** For each of AT-001.25, .26, .27, .28, .29, .30, .31, .33, .34, .35 and the new unlink id, the design names the body's Given, act and assertion at each tier, and where a clause has no surface locally (virtual keys, the vendor sign-in limiter) it names the declared red shape and the capability string. No id is left to "later".
5. **Smallest surface, deepest modules.** New edge functions, SQL functions, SUT members and harness helpers are counted and justified. Judgement lives in `supabase/functions/_shared/*` pure modules the fixture imports; the edge entry points stay thin; no rule is stated twice. Pass-through methods and temporal decomposition are absent.
6. **Fits the tree's posture.** New tables pass `_policy-scan.ts` (baseline revoke, no client write privilege, definer functions revoked from public, `viewer_` naming for policy helpers). The unlink refusal lives where Auth deletes the identity row or in front of it, with the ownership of `auth.identities` accounted for. The concierge escalation contact has a home that does not build the vetting surface early.
