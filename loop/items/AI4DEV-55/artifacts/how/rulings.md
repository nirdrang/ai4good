# Lead rulings on the architectural critique

Four critics read the explanation and the code: GPT-6 Astra at medium, Fable at medium, Grok 4.6 at xhigh, Opus at xhigh. Their reports sit beside this file as `critic-astra.md`, `critic-fable.md`, `critic-grok.md` and `critic-opus.md`. The lead ruled on every finding. "Act on" items bind the design that follows. "Consider" items the design may take or refuse with a stated reason. "Noted" items are true and carry no work here. "Dismissed" items are wrong or out of scope, with the reason.

One founder ruling entered this session before these rulings: AT-001.24 stays red at both tiers with a declared shape. This item lands AT-001.21, .22, .23 and .40 green.

## Act on

1. **One rule for reads, in SQL, exercised on every path.** Edge functions that read tenant data forward the caller's JWT to PostgREST (`apikey: <anon key>`, `Authorization: Bearer <caller token>`) instead of the service role, so the policy set is the single enforcement point for the UI path and for direct probing alike. TypeScript holds no second tenant rule; handlers shape and project rows the database already filtered. `resolveCaller` stays as the session-liveness gate. The project rule "UI never touches the database" holds: the UI calls an edge function, and the edge function reads as the caller. (Fable 1, Opus 1, Astra 1.)
2. **A viewer-shaped read in the harness, named apart from the operator read.** The contract gains read members that take a `Session` and run a PostgREST GET with that caller's token; the integration adapter reaches the token through the same private map every other session-taking member uses. The operator read stays and is the control that proves a row exists. Every tenant body uses both: operator to establish the row, viewer to establish the verdict. A body whose assertion rests on an operator read alone is a defect. Positive controls are mandatory, so an empty listing cannot pass. (Opus 6, Fable 4, Astra 4.)
3. **No hand-written policy mirror in the loop fixture.** A loop body grades shipped code only: handler orchestration run with injected reads, the exported refusal value, the public projection. Where a loop body can grade nothing shipped for an id, it throws `CapabilityPending` with the capability named, and the manifest declares that red at loop. A Map that re-implements the SQL policy set is a third copy of the rule and is refused. (Opus 2, Fable 4, Astra 4.)
4. **A durable guard that runs in CI.** CI runs the loop tier only, so the live catalog check alone would never run after merge. The design adds a loop-tier static check over `supabase/migrations/*.sql`: every `public` table appears in a declared list as unreachable-by-client-roles or tenant-isolated, and an isolated table shows RLS enabled, a grant, a policy, and no `using (true)`. The integration tier keeps the live catalog check over `pg_class`, `has_table_privilege` and `pg_policies`. The static half follows the precedent of `_source-scan.ts`; it adds no sentinel, fault, vendor stand-in or fixture world. (Opus 3, Fable 2 and 7, Astra 5.)
5. **State the client privilege posture once, then build on it.** The first migration step revokes every client-role privilege on every existing table, then grants exactly `SELECT` to `authenticated` where a policy will run. `anon` stays at zero on every table; the public surface is a function, not a grant. The header states the posture in one paragraph so the catalog check tests a stated rule. (Fable 2, Opus 7.)
6. **The no-existence-oracle property is structural.** One exported refusal value for reads, returned and never thrown, used for "no such row" and "not yours" alike, with nowhere in a handler to put a second one. Reads answer 404 with that value; the write path keeps its 403, and the design states why the two surfaces differ. The harness gains a sibling of `functionPost` that returns the raw text, so the equality assertion is over bytes. With reads as the caller, a keyed GET returns an empty list for both cases and no read-ordering discipline is needed; where a service-role read survives, the target row is read last and the design says why that read survives. (Opus 5, Fable 6.)
7. **The public project surface has one eligibility predicate.** The public projection is built one field at a time and gated by a single shipped predicate that says whether a project row may be shown to the world. Today that predicate returns true for every row, and its header says so and names the requirement that owns the lifecycle. No visibility column is added now, because a column nothing enforces is the defect the first migration refuses in its own words. (Astra 3, Opus 9.)
8. **Assignment grants access only to a volunteer.** The assigned-volunteer read policy checks the assignment and the account type. The assignment boundary gains a trigger that refuses a non-volunteer account in the seat, the way the membership trigger refuses a non-NGO grantee, so later readers stop compensating for a weak invariant. (Astra 6, Fable 3.)
9. **Policy helpers are marked and granted differently on purpose.** Any SECURITY DEFINER function a policy calls carries the `viewer_` prefix, `SET search_path = ''`, takes no argument that names another person, and is granted EXECUTE to `authenticated`. The migration header states the rule; the catalog check enforces it. Every other function stays `service_role` only. (Opus 7, Fable 3.)
10. **AT-001.24 stays red with a named shape.** No route registry ships; a registry no router imports reports a requirement nothing enforces. The loop body and the integration body throw `CapabilityPending` naming the UI-rendering capability, and the manifest declares both. The leaf that wires the auth screens turns the id green later. (Founder ruling; Opus 4, Fable 5, Astra 2.)
11. **Sign in right before each probe.** Access tokens live two minutes on the local stack. Integration bodies for the tenant ids register several actors through the mail catcher, so a body signs each actor in immediately before that actor's reads, or the viewer read refreshes when the token is near expiry. A stale token reads as 401 and must stay distinct from an empty list. (Fable 8.)
12. **Correct the two comments this deliverable falsifies.** `_contract.ts` says `org_memberships` reaches no Data API role, and `_live.ts` says the same of `projects`. Both become false with the policy set and are corrected in the same change. (Fable 4.)

## Consider

- **An own-row policy on `accounts` instead of definer helpers.** `id = (select auth.uid())` lets a policy read the caller's own type as the querying role, with no definer function exposed through `/rest/v1/rpc/`. It does not cover the platform admin's reach over other accounts, so at least one helper likely remains. The arena candidates choose and say why. (Fable 3.)
- **Drop the `SELECT, INSERT` grant on `accounts` to `authenticated`.** It exists for a superseded proof. Before removing it, confirm no body pins the RLS-layer message on an account insert; if none does, the normalisation step removes it. (Fable 2.)
- **Account type as a JWT claim through a custom access token hook.** Cheaper policies at listing scale, staleness bounded by the two-minute token. Not in this item: it is auth configuration and this leaf is already large. Record the analysis where the listing requirement will find it. (Opus 8, Fable 3.)
- **An isolation matrix each later resource must join.** Rightful NGO, assigned volunteer where applicable, platform admin, foreign NGO, unassigned volunteer, absent id. The catalog check guards tables, not storage links or external task reads. Write the matrix into the pull request's "Not done here" and the acceptance notes; it is a documentation change with its own ritual. (Astra 5.)

## Noted

- The tables the acceptance ids name do not exist; the green is over organisations, memberships, acknowledgments, volunteer profiles and projects, and the bodies and manifest say so. (Fable 7, explanation section 5.)
- Three documents disagree on how a read reaches the database, and one of them lives in `src/`, which this pull request cannot touch. The design names the chosen path (edge function reading as the caller); the founder files the correction to the front-end note. (Opus 10, Fable 5.)
- Splitting `AccountsSut` into per-system keys would let each tier bind only what it can answer. Right, and too large for this item; ruling 3 takes the cheap option. (Opus 2.)
- Two refusal vocabularies exist after this lands, 403 for writes and 404 for reads. Kept, with the reason stated in the refusal module. (Fable 6, Opus qualification 2.)

## Dismissed

- **"The deliverable should include coordinated front-end and harness dependencies."** (Astra 2.) Out of this item by founder ruling; the auth-screens leaf owns the route guard and its driver.
- **"An explicit default-private publication contract is needed before public reads."** (Astra 3, as stated.) Taken in reduced form as ruling 7: one predicate now, no lifecycle column, the owning requirement named. A contract with no state behind it would be the phantom column the tree refuses.
