AI4DEV-19 — AT-016.09's oracle, falsified on purpose. TWICE, for two different widenings.

CAPTURED AGAINST COMMIT 6c8fba8 ("AI4DEV-19: point the widened oracle at its own falsification, the
way the tightening already does"), the last code commit of the Gate 2 fix round. All four temporary
edits below were reverted afterwards and `git diff` against that commit is empty.

WHY THIS FILE WAS RE-CAPTURED. The Gate 2 round widened this oracle a second time (terra, finding
2): it read the transition and the event write while its own message claimed "the two must roll back
as one unit", and `emitKnown` also writes deliveries and an ops item after the fault point that
nothing ever inspected. Widening the oracle changed its message, so the previous transcripts quote
text no test can produce any more. Re-capturing rather than leaving them is the same discipline the
finding itself is about. The previous version is kept underneath, verbatim.

COMPANION FILES: proof-red.txt and proof-green.txt are the red-then-green pair for the ROLLBACK;
proof-restart.txt is the falsification for AT-016.07's restart. This file is the separate proof that
the oracle judging the rollback is strong enough to notice.

HOW THESE TRANSCRIPTS WERE CAPTURED. stdout and stderr were redirected to separate files rather than
merged: PowerShell wraps a native command's stderr in ErrorRecords when the two are merged, which
injects its own "NativeCommandError" text into the middle of a transcript. Only the stderr half is
reproduced for the failing runs, because that is where vitest prints the failure; the passing runs
have an empty stderr and are shown by their stdout summary. Every run used

    $env:AT_TIER='loop'
    bunx vitest run --root tests/at --config vitest.config.ts suites/req-016/c-reliability-guard.test.ts -t AT-016.09

to commit a delivery or an ops item and still pass — and `drainDeliveries()` would then have SENT
the leaked delivery. The widening was accepted on that argument. Whether the widening actually
discriminates is a separate question, and it is asked here for the same reason the first tightening
was asked it: an oracle that rejects nothing new bought nothing.
