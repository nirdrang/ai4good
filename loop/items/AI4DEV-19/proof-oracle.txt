AI4DEV-19 step 3b — the tightened AT-016.09 oracle, falsified on purpose.

COMPANION FILE: proof-red.txt and proof-green.txt are the red-then-green pair for the ROLLBACK; this
file is the separate proof that the oracle judging that pair is strong enough to notice.

Gate 0 finding 3 ruled that the old oracle - `if (transitionCommitted !== eventWritten)` - rejected
only UNEQUAL outcomes, so a fault firing AFTER both writes leaves both committed, compares equal,
and passes, having proved no atomicity at all. The ruling came with a verification condition: the
tightened oracle (both sides false) must FAIL when the fault point is deliberately misplaced. If it
passed, the tightening bought nothing and the ruling was wrong.

THE TEMPORARY EDIT, applied to tests/at/suites/req-016/_fixture.ts and then reverted: the
`reachFaultPoint(FAULT_POINT)` call was moved out from between the transition and the event write to
after the ops-item push - i.e. after BOTH writes - and the rollback removed with it, since with the
point there nothing is left half-committed to roll back. That is exactly the scenario the finding
describes: a crash that fires too late to prove anything.

Both runs below drive the SAME misplaced fixture. Only the oracle differs.
