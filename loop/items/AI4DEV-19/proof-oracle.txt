WHY THIS FILE WAS RE-CAPTURED, AGAIN. An earlier re-capture was forced by the output: the Gate 2
round widened this oracle to four reads, so the transcripts before it quoted text no test could
produce. This one is not forced by the output — the confirmation-round fix touches only AT-016.07,

`rulings-04.md` and binding this round too, is that every proof is captured against the FINAL code
commit with nothing changed afterwards, comments included; an earlier round broke that by adding a
cross-reference comment after capturing, which shifted line numbers inside committed stack traces. A
file that names a commit it was not taken against is stale evidence in the same way a file quoting a
dead message is, only quieter.

The previous version is kept below the banner, unchanged: it quotes "the two must roll back as one
unit, leaving neither", which nothing in this tree emits any more, so it cannot be reproduced. The
later sections are not kept, because they can be — the procedure below reproduces them exactly.

COMPANION FILES: proof-red.txt and proof-green.txt are the red-then-green pair for the ROLLBACK;
proof-restart.txt is the falsification for AT-016.07's restart, in two runs — the delivery path's
read of the process identity broken, and the restart call itself deleted. This file is the separate
proof that the oracle judging the rollback is strong enough to notice.

WHAT THIS FILE IS NOT EVIDENCE ABOUT. Round 2's two repairs — the event id that a crashed emit must
not consume, and the delivery stamp that belongs to the process which FIRST sent a row — are guarded
by conformance cases in tests/at/harness/conformance.selftest.ts, not by a transcript here. That is
deliberate and it is the lesson that round was ordered for: a captured falsification proves a repair
worked on the day it was taken, and a case left in the tree fails on the day someone undoes it.

HOW THESE TRANSCRIPTS WERE CAPTURED. stdout and stderr are redirected to separate files, and the
redirection is done by `cmd` rather than by PowerShell — PowerShell 5.1 wraps a native command's
stderr in its own ErrorRecords even when redirecting to a file, so a capture taken that way carries
NativeCommandError text the command never emitted and vitest's lines arrive hard-wrapped at the
console width. Only the stderr half is reproduced for the failing runs, because that is where vitest
prints the failure; the passing runs have an empty stderr and are shown by their stdout summary.
Every run used

    cmd /c "set AT_TIER=loop&& bunx vitest run --root tests/at --config vitest.config.ts suites/req-016/c-reliability-guard.test.ts -t AT-016.09 > out.txt 2> err.txt"
