AI4DEV-19 — AT-016.07's restart, falsified on purpose.

CAPTURED AGAINST COMMIT 6c8fba8 ("AI4DEV-19: point the widened oracle at its own falsification, the
way the tightening already does"), the last code commit of the Gate 2 fix round. `git diff` against
that commit is empty after the temporary edit below was reverted.

WHY THIS FILE EXISTS. Gate 2 (terra, finding 1) found that `processRestart()` assigned an epoch
string that NO code on the delivery path read, so deleting `await h.faults.processRestart()` from
AT-016.07 left the test passing identically. A step whose removal changes no outcome did not
participate in the result, and the green was unearned. AT-016.09 had been held to a captured
falsification (`proof-oracle.txt`) and AT-016.07 had not; that asymmetry is the finding. This file
removes it — the same standard, applied to the other test.

WHAT MAKES THE RESTART CAUSAL NOW. `Delivery` carries `deliveredByProcess`, created `null` and
stamped by `drainDeliveries` with the identity of the process that performed the send. AT-016.07
reads the epoch before and after the restart and requires every delivery of the event to carry the
POST-restart identity. The delivery path therefore has to read the process identity for the test to
pass at all.

THE TEMPORARY EDIT, applied to tests/at/suites/req-016/_fixture.ts and then reverted — it breaks the
coupling and nothing else. In `drainDeliveries`:

    delivery.deliveredByProcess = processEpoch;

becomes

    delivery.deliveredByProcess = 'delivery-process-1';

which is exactly what a delivery path that ignores the process identity looks like: a constant that
happens to equal the identity the process had before the restart.

HOW THESE TRANSCRIPTS WERE CAPTURED. stdout and stderr were redirected to separate files rather than
merged. PowerShell wraps a native command's stderr in ErrorRecords when the two are merged, which
injects its own "NativeCommandError" text into the middle of the transcript; separating the streams
keeps both verbatim. Vitest prints the run header and the summary on stdout and the failure detail on
stderr, so both are reproduced below under their own headings, in the order a terminal shows them.

    $env:AT_TIER='loop'

WHAT THIS PROVES, AND WHAT IT DOES NOT.

PROVES: the restart changes the delivery process's identity; the delivery path READS that identity;
and durable pending work was completed exactly once, by the identity that exists after the restart.
A `processEpoch` the delivery path ignores now fails AT-016.07 instead of passing it, which is the
mechanism terra named.

DOES NOT PROVE: that a restart loses and recovers in-flight work. At loop tier there is no volatile
in-flight state for a restart to lose — `drainDeliveries` is a synchronous sweep, not a process with
a lifecycle. Building a delivery worker with volatile state inside a stand-in fixture was FILED, not
built: inventing state whose only purpose is to be discarded would be staging the proof. Whoever
builds a real delivery process inherits that half.
