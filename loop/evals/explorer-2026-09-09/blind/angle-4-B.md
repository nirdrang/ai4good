### Non-Obvious Things

- Arming ≠ firing by design; `guards.ts` header and `faults.ts:4-9` call counting-armed-as-fired the catastrophe that would green every atomicity test with no symptom. `clear()` is the enforcement point, not `arm()` or the oracle.
- Live crash needs sequence because counter row would roll back; `nextval` is the only DB write surviving `RAISE`. Adapter must read `pg_sequence_last_value` before/after inside `append` (synchronous `arm/triggerCount` cannot await — `_live.ts:42-43`), and must match refusal `detail` string exactly; mismatch throws rather than returning 0.
- `implemented` list on crash switch (`_fault-switch.ts:40-44`) exists so silently accepting unimplemented kind does not arm nothing while reporting trigger — provider point reuses same object with `reject/lose_ack`.
- `drain({passes:1})` is load-bearing: quiescence drain makes reject and lost-ack intermediate `pending/retrying` unobservable and lets wrongly-mark-sent-on-`no_ack` fixture pass (`c-reliability-guard.test.ts:230-235`).
- `no_ack` carries `receipt:null` deliberately; SQL comment (`...outbox.sql:31-35`) says `accepted_at/receipt` are recovery facts, “not a way to skip the provider”; retry must reach provider, dedup is provider-side idempotency, not skipped call or stored receipt (`_provider-faults.ts:10-12`).
- Attempt-log at integration is explicitly single-witness (`_provider-faults.ts:13-16`): rejected/lost-ack never reach catcher, so only decorator’s log sees them; “would be wrong if decorator recorded a sequence it did not perform.” Catcher only witnesses physical-message count per key.
- `rememberAccepted`/`acceptedIdentities` dedupes on `[eventId,recipientId,channel]` JSON, not `key` string, to avoid delimiter collision (`vendors.ts:60-63`); rejected identity deliberately not protected so retry can succeed.
- Mail witness keys on Mailpit storage `ID` (physical identity), never collapses duplicates; a deduping reader could not see the defect it exists to see (`_mail-witness.ts:11-15`).
- Loop crash has one witness because “binding IS the code path” (`_fixture.ts:179-184`, `_fault-switch.ts:6-9`); live has two because adapter and product stand on different sides of wire. Equality (not just no-duplicate-among-selves) checked on both delivery and provider-accepted pairs to catch misdirected retry (`volunteer:email` vs `ngo:email` example at `c-reliability-guard.test.ts:281-287`).
- `event.attempts` is worker passes, not provider sends; in-app-only pass increments it with zero sends (`_contract.ts:106-114`); both counters checked because they can disagree.
- `deliveredByProcess` first-wins (`coalesce` in SQL, `if null` in memory) so stamp names actual sender, not last drain.
