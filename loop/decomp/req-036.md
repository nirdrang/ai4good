## Run structure [d99]

The PRD workspace tree runs as one parent run. The parent is AI4DEV-166 (PRD workspace); its open children are the units, in the order the blocked-by lines below allow.
The founder chose this on 2026-10-22 ("All", choosing "One run for the whole tree").
The flow every leaf builds to: the developer drives and there are no turns or handovers. Each section has its own chat, and only the developer posts questions to the NGO, who answers each in a side chat with the AI. The composer has no effort selector. 1. Derive screen records from the closed PRD, retain revisions and requirement links, and wire the badge carousel and stationary preview.
2. Enforce developer and NGO turns, question drafts, handoff, explicit return, unresolved questions, and actor-colored controls.
3. Materialize one UI development item per signed-off screen, with revision evidence and repeat-safe updates through the task-management writer.

The turn unit consumes the screen records. The sign-off unit consumes the screen records and turn authority.
The sign-off unit also consumes the task-management push primitive described in `req-026.md`.
It must prove that one screen can enter Build while another waits for the NGO.
