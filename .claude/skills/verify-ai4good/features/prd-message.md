# Send a PRD message

The Dev writes in the main chat and in a topic chat. The NGO administrator writes in a side chat for a question that was posted. A send reserves a turn, and the streamed path then asks the model to reply. The screen uses the stream. A JSON call reserves the turn and, except for a completion check, does not ask the model.

## How to reach it

Send `POST /functions/v1/prd-message` with `{ projectId, scope, requestId, baseRevision, intent }`. `projectId` is a uuid. `requestId` is a non-empty string. `baseRevision` is an integer. `scope` is `{ kind: "main" }`, `{ kind: "topic", topicId }`, or `{ kind: "side", questionId }` with a uuid question. `intent` is `{ kind: "text", text }`, `{ kind: "answers", picks, text }`, `{ kind: "use-answer", questionId, answer, note }`, or `{ kind: "close-check" }`.

JSON is the default. Send `Accept: text/event-stream` for the AI SDK UI message stream. The response headers are `content-type: text/event-stream`, `cache-control: no-cache`, `connection: keep-alive`, and `x-vercel-ai-ui-message-stream: v1`. Parts are `data: ` plus one JSON chunk, then a blank line, and the stream ends with `data: [DONE]`. A failure after the stream has started emits `{ type: "error", errorText }`. The port in `src/lib/prd-port.ts` holds chunks from `finish` and inserts one transient `{ type: "data-snapshot", data, transient: true }` part before releasing them. That part is added in the browser. It is not on the server stream.

## Drive and readback

A JSON text send answers 200 `{ ok: true, turnId, messageId, sequence }` from the reservation. The model runs only when the caller asked for the stream, or when the intent is `close-check`. A streamed text send writes the user message, a `prd_turns` row, a funds hold, then the provider events and ledger rows as the reply settles. A settled turn has left `admitted` and `uncertain`. The live reply is `answered`. A provider ledger row with `input_tokens` above 0 is a real model charge. Available funds fall by that turn's provider amount plus its fee once the hold is released. Read `prd_turns`, `prd_messages`, `prd_provider_events`, `prd_ledger_entries`, and `prd_fund_credits` over the operator SQL connection, or read `funds` on the next snapshot.

A text stream needs the model to be configured before the reserve. Without it the answer is 503 `refused` and the reason is "AI replies are not set up on this server yet." A JSON text send does not need the model. A completion check needs the model when no current check exists, on both JSON and the stream, and it needs funds. Closing the PRD from the screen starts as this check.

## Refusals

The shared write pipeline runs first, in the same order as open: 405 with no `kind`, 401 with no `kind`, 400 `invalid-request` for a non-object body, 400 `invalid-request` when the project id is not a uuid (the pipeline names that slot the organisation id), 502 `refused` for unreadable standing, 403 `account-deactivated`, 409 `no-account`, and 403 `refused` for an account type other than volunteer or NGO. The route then refuses 400 `invalid-request` when the project, chat, request, revision, or intent is missing or the wrong shape.

Preparation catches up an overdue turn in that chat, which can call the model only when a turn is already overdue. A streamed send that is not a completion check then requires the model (503 `refused`). A JSON send that is not a completion check does not. A completion check attaches the model id when settings exist and does not refuse here when they do not.

The reserve then checks, in order. The account must be active. An empty request or body hash is `invalid-request`. No PRD row is `invalid-request`. Pending or diverged is `not-yet`. The same actor repeating the same body returns the earlier result and does not charge again. A repeated request id with a different body, or a request id already used by an action, is `invalid-request`. No role is `forbidden`. The send gate then refuses: the Dev is the only sender in the main chat and in a topic chat, and the NGO administrator is the only sender in an open side chat. A role failure is `forbidden`. A missing chat, a bad side-chat id, or a missing side chat is `invalid-request`. The intent must be an object. Using an answer outside the main chat, running the completion check outside the main chat, or sending picks outside a topic chat is `invalid-request`. A closed PRD is `closed`. A completion check or a used answer against a different revision is `stale`. An open turn in that chat is `busy`. A completion check while any turn is open is `busy`.

A completion check then runs its own begin: the PRD must be open, not pending or diverged, and not closed; the caller must be the Dev; the chat must be the main chat; no turn may be open; and a new check needs funds (`funds`). A text intent with empty text is `invalid-request`. Picks must be a non-empty object of non-empty strings, with text only as a string. A used answer must name a question, a note, and wording that is a string or null; the question must be one for the NGO; the answer must still be the latest complete answer (`stale` from `prd_answer_use`). Any other intent kind is `invalid-request`. A funded reply then requires funds (`funds`).

Each database `kind` above is HTTP 409. A database failure that is not a five-character SQLSTATE is 502 `refused`. A completion check whose model result cannot be saved answers 502 with no `kind`. The cases a drive can prove with no model call are a JSON send, including a send after the PRD is closed.
