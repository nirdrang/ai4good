## Bootstrap and shared authoring

- **AT-036.01 (P0)** Given kickoff and approved Discovery, when the developer enters PRD, the PM scope requirements and bootstrap exist. The development tree remains empty until the planning package is written after UI Design. Initial topics and known answers reference the approved Discovery revision. Repeat entry creates no duplicate bootstrap or topics. [d101] When Dev first enters PRD, the project repository exists in the platform GitHub organization, private, created by the platform GitHub App with `main` protected against force-push and deletion, and its opening commit (the first commit that holds the PRD, after GitHub's empty initial commit) holds one markdown file per initial topic under `prd/`. The topic text the workspace shows is the read copy tied to that commit. Repeat entry creates no second repository and no second first commit. Cross: AT-026.06 owns seeding; AT-008.01 and AT-008.02 own the repository's home and timing.
- **AT-036.02 (P0)** Given the developer pulls the bootstrap, when Dev and AI author the PRD, the versioned PRD and shared record retain messages, actors, sources, decisions, revisions, topic chats, and NGO side chats. Reload preserves each human's drafts; there is no turn owner to restore. [d101] Each PRD revision is a commit in the project repository. A change one human makes appears in the other human's open workspace without a reload or any action by that human. Token attribution remains separate from provider-cost settlement. A failed attribution binding degrades honestly and never adds a funding bypass or an attribution money gate. Cross: task pull, attribution, and money retain their existing owners.
- **AT-036.03 (P0)** Given ready independent Dev questions, a dependent Dev question, and a decision only the NGO can make, when the AI chooses a round, it asks ready questions and explains why. It reuses facts, offers suggestions, and retains uncertainty. For the NGO decision it suggests a question for the NGO in its reply (`prd-ngo-question-intro`, "Suggested question for Maya (NGO) · not posted yet") with Post to Maya (`prd-post-question`) for Dev only; the question is not sent until Dev posts it. Answers determine subsequent questions. Topic selection never bypasses dependencies. Clarifications retain PM requirement or project anchors in the Q&A log. Cross: REQ-024/010 own blocker and log delivery.

## Coverage, spending, and materialization

- **AT-036.04 (P0)** Given a PRD missing a story, acceptance criterion, data-handling decision, and constraint, when scored against approved Discovery, the result identifies each gap with its topic and records the revision and configured threshold. Each gap appears in the AI's check message (`prd-check-gap`) with Open <topic> (`prd-check-gap-open`), and its topic goes to Needs review until Dev fixes it in the topic chat and confirms it again. The check runs when all required topics are confirmed and when Dev presses Close PRD, unless a check already ran for the current revision; a repeated Close PRD on a revision whose check found gaps shows that result again with no model call [d98]. Close PRD is off while the AI is answering in any chat, with "Wait for the AI to finish.", and when no check ran for the current revision and the funds cannot pay for one [d99]. The PRD panel shows the latest score and the threshold as a line [d99: screen wiring adds the line]. Confirmed topic badges cannot bypass coverage, and a failing score does not block closing (AT-036.16). The threshold stays configured, never invented by the test.
- **AT-036.05 (P0)** Given PRD authoring, NGO side-chat, scoring, and planning-package calls, when their Claude Managed Agents turns finish, the backend settles each model request's tokens, priced with versioned rates, once per model-request event, and the session runtime once per turn. Test normal and streaming replies, turns with several model requests, fractional cents, missing usage, duplicate events, retries, interrupted streams, and a turn the provider rejects before any model request, which releases its reservation. Missing usage stays pending until the session's events are read again. [d100] Ledger readback separates provider cost, the locked platform fee, total deducted, and token attribution; the chat shows no per-reply receipt. A repeated event or a second read of the session's events creates no second charge or model request. The composer has no effort selector; every request uses the configured service setting, and the backend records the effective provider settings.

## Topics, actors, and interface

- **AT-036.08 (P0)** Given Open, Draft, Ready to confirm, Confirmed, and Needs review topics, when the overview renders, the topic list (`prd-topic-list`, `prd-topic-item`, `prd-topic-state`, `prd-topic-blocker`) shows each state and blocker, and `prd-topic-progress` shows confirmed required topics out of the total. Only the AI sets Ready to confirm; only Dev confirms (`prd-section-confirm`) or reopens (`prd-section-reopen`, which sets Needs review). Changed answers invalidate affected dependents, lower progress where needed, and invalidate stale recommendations. Preserve unaffected confirmations. Each score remains a separate revision-linked event. Topic confirmation cannot close the PRD, change PM build status, or silently change the required-topic denominator. [d100] The AI changes topics only through the PRD tools: a reply's staged topics stay invisible until its commit and then land together; a commit is refused as a whole when any staged topic changed since the AI read it, and returns the current text; the PRD tools refuse a missing, forged, or expired token and a token for another chat or project. [d101] A reply's commit is one commit in the project repository that changes exactly the staged topic files under `prd/`; a refused commit leaves the repository's branch head unchanged. The AI session holds no repository credential and cannot push. Topic states and confirmations come from the platform database, never from the files.
- **AT-036.09 (P0)** Given Dev, NGO, an unrelated member, and stale tabs, when they call the backend directly, only Dev can write in the main chat and topic chats, post NGO questions, use an answer, confirm or reopen a topic, and close the PRD, at any time and with no turn to own. The NGO can write only in the side chat of a question posted to it and mark that answer complete; it cannot start a question, close, change the threshold, override scoring, or read development board content. Unrelated users cannot read or write. Stale recommendations, duplicate actions, and simultaneous sends leave consistent history. Ordinary AI continuation has no state-action button.
- **AT-036.10 (P0)** Given long history, when the actual workspace renders, AI, Dev, and NGO retain their colors and names throughout (`prd-turn`, `prd-chat`). There are no bookmark buttons and no turn or handover controls. Close PRD appears in the PRD panel (`prd-close-panel`) and inline with the AI's completion message (`prd-recommendation`). The composer (`prd-composer`) has no effort control. Keyboard, narrow layout, and both themes preserve readable state and reachable controls. NGO and public projections exclude development board content. Gap reports and the completed-package backlog-live notification use the registered emitter with duplicate protection; no gate-passed notification is sent [d99].

## NGO questions, topic chats, closing, and the phone

- **AT-036.13 (P0)** Given Dev posted a blocking question to the NGO, when the NGO opens it from the question list (`prd-ngo-question-list`, `prd-ngo-question-open`) or from Answer it on the chat card (`prd-ngo-question-answer`), a side chat with the AI opens (`prd-side-chat`) with suggested answers (`prd-side-chat-option`), an input (`prd-side-chat-input`), and Send (`prd-side-chat-send`). Before the NGO writes anything, Mark answer complete (`prd-side-chat-complete`) is off. After "a year", the AI's reply records a follow-up as open; the screen reads that from the reply's outcome, never from a question mark in its text [d99]. Mark answer complete is then off and `prd-side-chat-complete-hint` reads "Answer the AI’s question first." After the NGO replies, the button turns on. On Mark answer complete, the NGO returns to All questions, the question shows `prd-ngo-question-sent` with one clean answer the AI wrote from the chat (for example "Keep a volunteer’s email and phone for a year, then delete them. Shift history stays, without names."), and Dev's list shows it complete with View answer and Use answer. A question the NGO asks the AI inside the side chat is answered there and never becomes part of the answer. The side chat's replies are paid from the PRD funds.
- **AT-036.14 (P0)** Given a completed NGO answer, when Dev selects View answer (`prd-ngo-question-view`), the review (`prd-answer-review`) shows the answer editable (`prd-answer-review-answer`), the PRD impact and open points, and a note box (`prd-answer-review-note`). When Dev selects Use answer (`prd-ngo-question-claim`, or `prd-answer-review-claim` in the review), a brief (`prd-claim-brief`) posts as Dev's blue message in the main chat, with the rows Question, the NGO's answer, I changed it to (only when Dev edited it), How the answer was reached, What it changes, To discuss (the open point), and My note (only with a note). No row or line assumes a pronoun for the NGO or Dev [d99: screen wiring replaces "How she got there" and the other pronoun copy]. Use answer is off while the AI is answering and when the funds are short [d99]. After the brief posts, the AI replies: it records the answer in its topic, tells the NGO the final wording if Dev changed it, and raises any open point; a note settles the point and is written into the topic. The question moves to Answered (`prd-answered-toggle`, `prd-answered-question`); selecting it shows its brief in the main chat.
- **AT-036.15 (P0)** Given Dev opens a topic from the topic list, the topic shows as a document (`prd-section`, `prd-section-text`, `prd-section-state`, `prd-section-status`) with every assimilated decision and its sources as plain names, with no links to source messages [d99], and for the technical scope its numbered user stories (`prd-section-stories`, `prd-section-story`); it lists no conversation history. A topic in Needs review after a change shows one line, "Changed since you confirmed: ...", saying what changed [d99]. Confirm is off while a topic it depends on is not Ready to confirm or Confirmed, and while a completion-check gap on it is open; when confirming would start the completion check, it is also off while the AI is answering and when the funds are short [d99]. The topic's own chat sits below (`prd-section-chat`, `prd-section-message`, `prd-section-input`, `prd-section-send`), with the current PRD and approved Discovery as context. A change Dev asks for there is written into the document as a plain statement. Shift questions for Dev appear in that topic's chat (`prd-question`, `prd-question-option`). The NGO sees the same document and chat read-only, with the line "Priya works on this section with the AI. You can read along." [d99] The topic chat persists across visits.
- **AT-036.16 (P0)** Given a PRD with unconfirmed topics and unchecked coverage, Close PRD (`prd-close-button`) is available to Dev from the start, under the panel's "Still open" list (`prd-close-remaining`, `prd-close-remaining-item`). Pressing it runs the completion check; with gaps or unconfirmed topics the AI lists them with Close anyway (`prd-close-anyway`) and Keep working (`prd-close-keep`). Keep working leaves the PRD open. Close anyway closes it and records the open points in the closed revision (AT-036.06). After a passing check for the current revision, Close PRD closes at once; after a failing one, it shows the warning again without a new check [d98]. Close PRD is off, with "Wait for the AI to finish.", while the AI is answering in any chat, and off when no check ran for the current revision and the funds cannot pay for one [d99]. An open blocking question to the NGO counts as an open point: it brings up Close anyway and Keep working even after a passing check, and Close anyway records it as open [d99: screen wiring adds this warning]. The "Still open" lines include sections waiting on another section and sections still being written, and each line opens what it names [d99]. The NGO sees "Only Priya can close the PRD." and no close control.
- **AT-036.17 (P0)** Given the AI is answering in a chat, when the person who writes there sends more messages (`prd-send-button` reads Add to queue), they wait in that chat's queue (`prd-queue`, `prd-queue-item`) and are sent in order, each as its own paid request. This holds in every chat: the main chat, each section chat, and the NGO side chat [d99: today only the main chat queues; screen wiring adds the others]. A queued plain message can be edited (`prd-queue-edit`) while the input box is empty, and removed (`prd-queue-remove`) until it is sent. A queued Use answer or Close PRD item can only be removed [d99].
- **AT-036.18 (P0)** Given the phone at 390 by 844, the workspace has three tabs (`phone-tab-bar`: `phone-tab-chat`, `phone-tab-prd`, `phone-tab-questions` with `phone-tab-questions-badge`). The NGO opens on Questions; Dev opens on Chat. Every label fits on one line. An opened topic is one page with one scroll (`prd-section-page`): the document at full length, then a Section chat divider and the chat, starting at the top of the document, with Dev's input pinned below; `prd-section-back` returns to the topic list.
